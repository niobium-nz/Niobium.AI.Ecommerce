# Quality gates

## Before production

Confirm actual pixel access to every selected source and identify the same single
SKU. Resolve material conflicts and determine whether any source view was
mirrored before relying on handedness. Do not reverse a view merely to resemble
another. Record the source support for all planned views and critical details.

Require sufficient coverage or explicit acceptance of a supported-view-only
board. Do not interpret a simple instruction to proceed as permission to invent
unknown sides. Confirm that required views and critical features remain covered.
Require at least two distinct supported views and one coherent main configuration.
Use front/back/side/top as a planning checklist, not a quota to fill by inference.
Inspect the underside and the other side whenever they contain unrepresented
material features; never silently call unobserved sides identical.

Identify the logo-removal regions and ensure that edits will not destroy functional
marks or unknown structure. Confirm that the chosen editor can receive the actual
source images, produce one transparent PNG, and expose an output for inspection.
Do not proceed using filenames as substitutes for image inputs.

## Candidate comparison checklist

| Gate | Pass condition |
| --- | --- |
| Identity | Every view depicts the same SKU and intended configuration; no hybrid product. |
| Coverage | Every depicted surface is evidenced; accepted missing coverage is not invented or called complete. |
| Silhouette | Outline and topology match the source, excluding only supported cosmetic brand relief removal. |
| Proportions | Width/height/part relationships are preserved; no stretching or idealization. |
| Handedness | Left/right relationships match evidence; no mirrored substitute. |
| Components | Same count, attachment points, openings, ports and visible moving parts. |
| Construction | Seams, joints, texture, fasteners, edges and thin elements remain intact. |
| State | No open/closed hybrid or ambiguous separated part masquerading as another product. |
| Color/material | No brand-color recoloring, substituted material, gloss invention, or unsupported tint correction. |
| Markings | Logos/brand text removed; legible supported functional markings retained. |
| Noise | No people, hands, scene props, retail packaging, promotional text, source watermarks or background. |
| Isolation | No cutout halos, missing transparent parts, cropped edges or foreground residue. |
| Scale/layout | Complete views at consistent apparent scale, coherent alignment and clear nonoverlapping gaps. |
| Transparency | Actual PNG alpha; not painted checkerboard, white background, or fake transparency. |
| Presentation | One neutral board; no added labels, captions, arrows, measurements, frames or marketing styling. |

Check alpha in the host's transparency/metadata tools where available. Preview on
contrasting backgrounds when possible to reveal edge residue, but do not export
those backgrounds or deliver the previews as extra images. Do not infer successful
transparency solely from a checkerboard thumbnail or the PNG filename extension.
Retain genuine semitransparency of the product; do not make every foreground
pixel opaque. If reliable output inspection is unavailable, do not claim it passed.

Review source and candidate at enough resolution to inspect the smallest critical
feature. Do not report numeric geometry accuracy from a visual comparison alone.
Masks, reference conditioning and larger output dimensions are not proof of exact
fidelity. Never assert a physical measurement or complete all-angle reconstruction.

## Failure and correction

For an obvious local editing artifact, perform a targeted correction supported by
source evidence and recheck the entire changed view. If the same structural issue
persists or new edits keep altering other parts, stop rather than repeatedly
regenerating. Request a clearer source or an appropriate image-editing capability.
Do not distribute a knowingly failed candidate as the finished reference board.

Use focused plain-text clarification for missing views or visual conflicts. Use
the JSON error contract for inaccessible files, unavailable tools, invalid input,
or a failed production process. Do not produce a blank board or a visually
invented placeholder merely to satisfy the single-image output requirement.

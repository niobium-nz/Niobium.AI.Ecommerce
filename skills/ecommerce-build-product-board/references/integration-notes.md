# Integration notes

## Downstream reference

The PNG can be used as `product_reference_board` for Ecommerce Image Strategist
by supplying a real accessible image URL or a local path that exists in the
receiving host. An attachment may need to be made available to that host first.
Do not invent a local path or assume an attachment in one environment is readable
in another. The image file itself, not just its name, is the reference.

Keep the single-SKU convention explicit in downstream context: repeated views are
angles of one item, not quantities, accessories, alternate variants, or a bundle.
The board is intentionally debranded. Do not restore removed marks from memory.
It does not prove that a manufactured unbranded SKU exists, that new colors are
available, or that invisible surfaces match a familiar product.

An incomplete board remains incomplete downstream. Explicit acceptance of missing
views for this builder does not waive another skill's stricter fidelity checks.
Carry missing-view limitations forward in task context and keep the original
photographs available when higher-fidelity clarification is needed. Do not
silently modify the other installed skill or expand its input schema.

## Package contents and use

Keep the skill name `Ecommerce Build Product Board` and identifier
`ecommerce-build-product-board`. Follow the same Ecommerce + Verb + Noun naming
pattern for this skill. The package contains instructions, language-agnostic
input/error schemas and fictional examples. It contains no source-language
models, retained original specification, executable scripts or generated product
images. The optional plugin wrapper packages the same files; it does not provide
or authenticate missing image tools, install itself or publish anything.

The skill is designed for hosts that can load its resources and inspect/edit
actual images. Script-free does not mean tool-free. The no-code instructions are
not proof that a particular platform exposes every required capability. Respect
host output restrictions and permissions rather than changing them.

## Approved adaptations

Replace the original inferred-angle rule with evidence-only coverage, and replace
majority-vote conflict resolution with explicit SKU/state resolution. Examine
useful product regions even in noisy photos. Prefer source-preserving cleanup
and composition over full reconstruction. Preserve actual colors and functional
markings while removing all branding, including on-product marks, as the user's
final correction requires. Treat the transparent board as one output image, not
as JSON or separately delivered view files.

Do not promise deterministic pixels, mathematical geometry recovery, or complete
knowledge of every angle. Claim only the checks actually performed on real
sources and the actual final candidate.
